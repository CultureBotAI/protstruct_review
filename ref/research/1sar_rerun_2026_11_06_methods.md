## 2. Supported CLI Invocation and Entry-Point Sources

```bash
uv run --locked --extra benchmark -- python scripts/onesar_rerun.py \
  --subject R4 \
  --family rfactors \
  --evidence-out <fresh-repository-local-directory>
```

- **CLI and environment boundary:** `--subject` uses `normalize_cli_subject_id` and `CLI_SUBJECT_ALIASES` (exact lookup for `start`, `R4`, `R5`, `R6` and aliases `r4`, `r5`, `r6` without whitespace trimming; `R7`, `r7`, `all`, and unknown values raise `ValueError`). `--family` uses `validate_cli_measurement_family` and `ALLOWED_CLI_MEASUREMENT_FAMILIES` (`"rfactors"` only). `--evidence-out` uses `prepare_fresh_evidence_root`, requiring a non-existing path inside `repo_root`, rejecting symlinked ancestor/leaf paths with `ValueError`, and rejecting preexisting files/directories with `FileExistsError`. - **Entry points:** See `build_arg_parser`, `parse_cli_args`, and `run_single_subject_rfactor_attempt` in `scripts/onesar_rerun.py`, and `publish_retained_rfactor_records` in `scripts/onesar_records.py`.

## 3. Retained Single-Subject Lifecycle

1. **Start timestamp, UTC `run_date`, and parent start record:** After pre-admission checks and before `prepare_fresh_evidence_root`, `run_single_subject_rfactor_attempt` derives `started_at_utc` and `run_date` from `datetime.now(timezone.utc)` (or parses `started_at_utc_override` via `datetime.fromisoformat`, requiring a timezone and converting to UTC); `authoring_policy_issued_at` (`issued_at`) is separate. After `prepare_fresh_evidence_root` creates the parent directory, it writes `PARENT_ATTEMPT_STARTED_FILENAME` (`PARENT_ATTEMPT_STARTED_STAGE`) via `_write_exclusive_parent_json_record` (`O_CREAT | O_EXCL | O_NOFOLLOW` open, file `fsync`, best-effort directory `fsync`, `lstat` regular-file check, and reopened byte equality) before the protected `try` block.
2. **Sequential producers and manifest binding:** Inside `try`, orchestration resolves target paths via `onesar_records._resolve_rfactor_record_identities`, runs Producer 1 (`run_phenix_rfactor_operation`, calling `refinement_cache.cached_phenix_operation` and `reconcile_phenix_rfactor_output`), and binds `phenix_reconciled_manifest.json` via `_bind_phenix_reconciled_manifest_reference` (checking regular-file containment, digest, size, required keys, and non-self-reference). It then runs Producer 2 (`onesar_refmac.run_refmac_rfactor_operation`) and binds `refmac_operation_manifest.json` via `_bind_refmac_operation_manifest_reference` (verifying the regular file, setting `persisted: True` when omitted (`#1095`), and deep-copying `manifest_json` to preserve fallback ancestry). Normal REFMAC return is `status == "diagnostic_captured_gates_unproven"` (diagnostic capture, not scientific admission).
3. **Completed execution checkpoint:** Only if both producers return normally and both manifests bind does `run_single_subject_rfactor_attempt` build the checkpoint via `onesar_records.build_parent_completed_execution_checkpoint_payload` (`REQUIRED_PARENT_EXECUTION_CHECKPOINT_KEYS`, `FORBIDDEN_PARENT_CHECKPOINT_AUTHORING_OUTCOME_KEYS`, and strict timestamp lexical/order validation) and write `PARENT_COMPLETED_CHECKPOINT_FILENAME` via `_write_exclusive_parent_json_record`.
4. **Retained verification and authoring outcomes:** `onesar_records.publish_retained_rfactor_records` re-verifies the checkpoint (`verify_retained_parent_execution_checkpoint`), PHENIX evidence (`verify_retained_phenix_rfactor_evidence`), and REFMAC evidence (`verify_retained_refmac_rfactor_evidence`), always refuses scientific admission (or raises on earlier errors) under the current contract, and writes refusal diagnostics under `<parent A>/authoring_outcomes/authoring_outcome_<NNNN>.json`. Canonical destinations are defined by `onesar_records.DEFAULT_RECORD_DESTINATION_REL` (`data/coscientists/openscientist`) and `_resolve_rfactor_record_identities` (`_SUPPLEMENTAL_SUBJECT_TAGS`).

## 4. Failure, Scientific, and Authorization Boundaries

- **Outcome retention and error precedence:** `PARENT_ATTEMPT_OUTCOME_FILENAME` (`PARENT_ATTEMPT_OUTCOME_STAGE`) is written and attached only after entering the protected producer/publication `try` block; failures during pre-admission checks, `prepare_fresh_evidence_root`, output-root resolution, or writing `parent_attempt_started.json` occur before `try` and write no outcome file. In `except BaseException as exc:`, classification preserves `commit_state == "committed"` (`status = "published"`) and `commit_state == "unknown"` (`status = "unknown"`) ahead of `KeyboardInterrupt` (`status = "interrupted"`), record-layer refusals when `current_stage == "publish_retained_rfactor_records"` (`status = "refused"`, with `failed_stage = "refmac_retained_verification"` on normal scientific refusal), and other errors (`status = "failed"`). Child inventories (`_collect_phenix_attempt_inventory`, `_collect_refmac_attempt_inventory`) probe roots (`_probe_inventory_evidence_root`) and manifest-linked candidates (`_inspect_regular_file_reference_under_root`); root or file errors set `inventory_status = "unavailable"` and `inspection_error` without aborting outcome persistence. If writing `parent_attempt_outcome.json` fails, `outcome_record_reference` is `None` and `outcome_persistence_error` is recorded separately on `attempt_outcome` while preserving the original exception and commit state.
- **CLI exit codes (`scripts/onesar_rerun.py::main`):** `--help` returns `0`; pre-admission rejections return `2`; `KeyboardInterrupt` is re-raised after outcome handling; and post-admission paths return `0` only on a clean `"published"` outcome with persisted `parent_attempt_outcome.json`, returning `1` otherwise.
- **Preregistered gates, eligibility flags, and diagnostic `R4` sequence:** In `refmac_diagnostics.json` and `refmac_operation_manifest.json`, each `preregistered_gates` entry (`_REQUIRED_REFMAC_PREREGISTERED_GATE_KEYS` in `scripts/onesar_records.py`) is a mapping whose `.get("proven")` boolean reflects respective checks for gates 1 and 2 (`True` on clean diagnostic capture; `False` when a check fails on a retained failure path), additionally requires the XYZOUT model-preservation audit (`model_preservation_proven`) for gate 6 and can remain `False` on a normal diagnostic return, and is `False` for gates 3–5 (`REFMAC_UNKNOWN_NATIVE_PREMISE_KEYS`) in the current collector, while all six scalar flags in `REFMAC_FALSE_ADMISSION_ELIGIBILITY_KEYS` are `False`. Integrity verification alone cannot authorize `EVAL` or `QDS` publication. Under standing authorization, one diagnostic `R4` run follows accepted implementation, fresh review, and green QC (`scripts/validate.sh`); native HKL selection, bin membership, and residual reconstruction (gates 3–5) are evaluated from those retained diagnostic outputs, not required beforehand. Canonical `EVAL`/`QDS` authoring and batch execution remain blocked until an accepted scientific canary both proves those gates and wires an accepted scientific admission/return contract into `publish_retained_rfactor_records`.
