## 4. Explicit Methodological Protocols and Non-Comparability Rules

### 4.1 PHENIX First-Block `model_vs_data` Public API Adapter and HKL Ledgers

High-level `mmtbx.model_vs_data.run()` reads `REMARK 3` resolution limits from the input PDB header and may rebuild and rescale a second `fmodel` before returning, and its CLI exposes neither an ignore-header switch nor an explicit free-test-value parameter. To guarantee that the first-block calculation, exported `fmodel` arrays, and map coefficients all describe the exact same untouched PDB input and full MTZ range:

1. Construct the reflection-file server from original `data/1sar.mtz`, extract `extract_xtal_data.data_and_flags_master_params().extract()`, set observation labels `F-obs,SIGF-obs`, flag label `R-free-flags`, and `parameters.r_free_flags.test_flag_value = 1`, require flags, and disable flag generation.
2. Call `extract_xtal_data.run(...)` and fail closed if any extraction errors accumulate (`iotbx/extract_xtal_data.py` accumulates errors under `keep_going=True` in the vendor CLI). Require a non-empty retained flag array with disjoint, non-empty work and free sets (`1 = test`) so `mmtbx.f_model`'s all-work fallback can never masquerade as `R-free`.
3. Construct `iotbx.pdb.input` and `mmtbx.model.manager` from the original PDB bytes using the default `n_gaussian` scattering table, build `mmtbx.f_model.manager(xray_structure=..., f_obs=..., r_free_flags=..., twin_law=None)`, call `update_all_scales(update_f_part1=True)`, and snapshot scatterer coordinates, occupancies, and ADPs before and after scaling (`apply_back_trace=False`).
4. Because `cctbx.miller` regularization and `update_all_scales` (`remove_outliers=True`, low-resolution bin filtering, `apply_scale_k1_to_f_obs=True`) can filter and rescale observations in a model-dependent way, export four separate HKL ledgers:
   - original raw MTZ rows,
   - repository input-policy eligible rows (finite `F`, positive finite `SIGF`, valid `{0, 1}` flag),
   - extracted pre-scaling observations, and
   - final effective work and free sets (`fmodel.f_obs_work()`, `fmodel.f_obs_free()`), preserving original `F-obs/SIGF-obs` alongside transformed `f_obs`.
5. Export full-precision `fmodel.r_work()` and `fmodel.r_free()`, complex model arrays `f_model_scaled_with_k1_w()` and `f_model_scaled_with_k1_t()`, per-set counts, numerator `Σ|F_obs − |F_model_scaled||`, denominator `Σ F_obs`, resolution extrema, and separate work/free scale factors `scale_k1_w()` and `scale_k1_t()`. Because PHENIX fits `scale_k1_t()` on the free set, a single globally scaled `Fc` array cannot replay both native R values; retain the exact per-set scaled arrays and validate direct arithmetic replay against `fmodel.r_work()` and `fmodel.r_free()`.
6. Export `2mFo-DFc` and `mFo-DFc` coefficients from the same first-block `fmodel` (`fill_missing=False`, `exclude_free_r_reflections=False`, `isotropize=True`), recording their HKL sets separately from the R-factor denominator ledger. Never infer observed R-factor HKL membership from map coefficient arrays.

### 4.2 REFMAC5 Fixed-Model Protocol and Fail-Closed Effective-Selection Audit

1. Invoke `REFMAC5` via `scripts/toolchain.py::run_refmac` with explicit stdin keywords:
   ```text
   LABIN FP=F-obs SIGFP=SIGF-obs FREE=R-free-flags
   FREE 1
   REFI BREF MIXED
   NCYC 0
   END
   ```
   plus explicit `LABOUT` labels for calculated structure factors and map coefficients (`FWT`, `PHWT`, `DELFWT`, `PHDELWT`). `FREE 1` is mandatory because REFMAC defaults to `FREE 0`; `REFI BREF MIXED` preserves the input PDB's isotropic-only ADP membership (whereas `BREF ANIS` converts every atom to anisotropic); and `NCYC 0` performs zero coordinate cycles.
2. Retain the complete keyword file, stdout/stderr logs, `XMLOUT` (if produced), output MTZ, and output PDB. Verify that output coordinates and occupancies match the input PDB, and audit any overall-B shift written to output ADPs. Never pass REFMAC's output PDB forward as the untouched input model, and only pass it as `PDBIN` to the explicit `edstats` subprocess pipeline (`mtzinfo` → `mtzfix` → `fft` → `edstats`) after proving exact atom mapping and unchanged coordinates/occupancies while disclosing any overall-B offset.
3. **Fail-closed effective-selection and reconstruction reconciliation:** In REFMAC output MTZs, `FP/SIGFP` are rescaled, output `FC` omits `FPART` bulk-solvent contributions, and missing-`FP` rows can still receive finite `FWT = dFC` and `DELFWT = 0`. Raw output row counts or finite map-coefficient counts therefore never establish effective R-factor denominators. Before accepting a REFMAC measurement, reconcile all six checks:
   - one-to-one input/output HKL mapping with unchanged symmetry and indexing,
   - preserved original free-flag membership (`1 = test`),
   - no newly finite observations or unexplained missing observations,
   - final observed work and free cardinalities equal to the summed final log-bin `NR_used` and `NR_free`,
   - per-bin membership/counts and resolution extrema consistent with log precision, and
   - R-work and R-free reconstructed from the appropriate total scaled model-amplitude output agreeing with native printed R values at stated log precision (reporting native printed and MTZ-reconstructed values distinctly).
   If any check fails to reconcile, retain all raw outputs, record `effective_selection_unproven`, and do **not** publish a matched or inferred denominator.

### 4.3 Non-Comparability and Threshold Governance

- Compare exact effective work and free HKL sets across `PHENIX` and `REFMAC5` and across `start`, `R4`, `R5`, and `R6`. Even within `PHENIX`, model-based outlier rejection can make `start` and `R4` use slightly different effective HKL sets.
- Whenever native effective selections, map definitions, or mask radii differ, label the pair `non-comparable` (`not_comparable_mask_and_map` for native PHENIX vs EDSTATS density). Never average across tools or force equal denominators by disabling vendor outlier rejection on the primary native path (any common-intersection calculation is a separate descriptive sensitivity check, not a native refit).
- Do **not** transfer the registry §3 `gemmi sfcalc` direct-summation `R-work` offset band (`|ΔR_work| ≤ 0.02`, `ref/thresholds_and_standards.md`) to the `PHENIX` vs `REFMAC5` comparison. No registry threshold is modified and no pass/fail model-quality verdict is issued.
