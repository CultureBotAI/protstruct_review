# Question-Based Guide to Macromolecular Structure Tools and Measurements

This guide organizes the repository's 17 macromolecular crystallography, cryo-EM, NMR, and structure-prediction tasks (`T01`–`T17` in [`ref/catalog.yaml`](catalog.yaml)) around the **scientific questions** a structural biologist or automated evaluation harness needs to answer when assessing a model or a before/after refinement workflow.

Rather than treating tool outputs as interchangeable pass/fail numbers, this guide syntheses [`ref/catalog.yaml`](catalog.yaml), [`ref/tool_recommendations.yaml`](tool_recommendations.yaml), [`ref/tool_assumptions.yaml`](tool_assumptions.yaml), [`ref/threshold_evidence_status.yaml`](threshold_evidence_status.yaml), [`ref/structural_criteria.yaml`](structural_criteria.yaml), [`ref/oracle_tools.md`](oracle_tools.md), and [`ref/quality_reporting.md`](quality_reporting.md) across **four distinct epistemic layers**:

1. **Documented capability**: What the task catalog and upstream primary tool documentation define as the observable, producer, and mathematical convention.
2. **Runnable local integration**: Which CLI binaries, Python packages, and repository wrapper scripts (`scripts/gemmi_rfactor.py`, `scripts/t13_data_quality.py`, `scripts/t15_ss_agreement.py`, `scripts/t16_interface_quality.py`, `scripts/t17_nmr_ensemble.py`, `scripts/t17_restraint_summary.py`, `scripts/checkmymetal_local.py`, `scripts/audit_1sar_retained_evidence.py`, `scripts/assess_refinement.py`) are wired and executable in this repository. External tools use their documented configuration and installation requirements; supported centralized routes are defined in `scripts/toolchain.py`.
3. **Retained independent evidence**: What empirical measurements are actually stored on disk in `data/coscientists/openscientist/EVAL_*.yaml` and `data/examples/eval/EVAL_*.yaml` (`EVAL_*`), `data/coscientists/openscientist/QDS_*.yaml` and `data/examples/qds/QDS_*.yaml` (`QDS_*`), the 21-row registry inventory [`ref/threshold_evidence_status.yaml`](threshold_evidence_status.yaml), and `ref/research/data/`, including explicit deliberate oracle gaps, missing-artifact waivers, and stopped or access-blocked campaigns.
4. **Calibrated interpretation vs informational reporting**: Which clauses in [`ref/thresholds_and_standards.md`](thresholds_and_standards.md) (§1–§6) and [`ref/threshold_evidence_status.yaml`](threshold_evidence_status.yaml) (`policy_state` and `evidence_state` per component) have retained benchmark or literature support, which recommendations have active capability corrections or suspensions in [`ref/tool_recommendations.yaml`](tool_recommendations.yaml), and why before/after comparisons remain **informational** unless bound to an adopted `StructuralQualityCriterion` (`pass_criterion_bindings` is currently `[]` across all retained `EVAL_*.yaml` and `QDS_*.yaml` records under [`schemas/protstruct_review.yaml`](../schemas/protstruct_review.yaml)).

## 2. Epistemic Framework: Four Layers of Tool & Measurement Evidence

Every tool recommendation and measurement in this repository must be interpreted across four explicit layers:

```
┌────────────────────────────────────────────────────────────────────────────┐
│ Layer 1: Documented Capability (`ref/catalog.yaml`, primary tool manuals)  │
│ Defines the intended observable, mathematical formula, and candidate tools │
└──────────────────────────────────────┬─────────────────────────────────────┘
                                       ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ Layer 2: Runnable Local Integration (`scripts/*.py`, `.venv`, CLI paths)   │
│ Verifies which binary/script actually executes on the workstation and what │
│ flags/inputs it requires (`ref/tool_recommendations.yaml`)                 │
└──────────────────────────────────────┬─────────────────────────────────────┘
                                       ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ Layer 3: Retained Independent Evidence (`EVAL_*`, `QDS_*`, `data/*.json`)  │
│ Records exact input SHA-256 digests, tool versions, sample sizes, and      │
│ explicit gaps/waivers (`ref/threshold_evidence_status.yaml`)               │
└──────────────────────────────────────┬─────────────────────────────────────┘
                                       ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ Layer 4: Calibrated Interpretation vs Informational Reporting              │
│ Applies active assumptions (`ref/tool_assumptions.yaml`) and separates     │
│ empirically calibrated tolerances from uncalibrated/informational metrics  │
└────────────────────────────────────────────────────────────────────────────┘
```

### Critical Rules When Crossing Layers
- **Do not infer runnable capability from a catalog name**: Two catalog entries previously assigned capabilities that the underlying CLI binary does not implement (`gemmi validate` does not compute bond/angle/planarity RMSD, chirality counts, $\omega$ flips, or Wilson $B$, corrected under `#785`; `ProSMART` is a reference-dependent structural comparison tool and does not compute a single-model Top8000 Ramachandran-Z score, corrected under `#911`). Always consult [`ref/tool_recommendations.yaml`](tool_recommendations.yaml) for active `role: deprecated` or `role: suspended` records before invoking a tool.
- **Do not treat retained observations or waivers as substitutes for missing coordinates**: In `data/coscientists/openscientist/EVAL_1sar_cdba2c07_2026-09-23.yaml` and `data/coscientists/openscientist/QDS_1sar_cdba2c07_2026-09-23.yaml`, the packaged archive retains `data/1sar_final.pdb` (the round-4 model, `1sar_4_refine_001`) while `claude_iterations.log` and the narrative report describe round 7 (`1sar_7_refine_001`). Retaining round-4 coordinate and data audits (`data/coscientists/openscientist/retained_evidence_2026-09-23/coordinate_and_t13_audit.json` and `ref/research/data/refinement_assessment_1sar_and_controls_2026-10-18.json`) characterizes the retained artifact and proves the provenance gap, but does not validate the absent round-7 model.
- **Do not promote informational deltas into automated pass/fail verdicts without criterion bindings**: Across every retained `EVAL_*.yaml` and `QDS_*.yaml` record in `data/coscientists/openscientist/` and `data/examples/`, `pass_criterion_bindings` is currently `[]`. Before/after refinement assessments in [`scripts/assess_refinement.py`](../scripts/assess_refinement.py) therefore return `assessment_verdict_status: "informational"` via `resolve_verdict_status()` whenever `pass_criterion_bindings: []`.

## 3. Category 1: Experimental Fit & Data Quality (`T03`, `T04`, `T06`, `T08`, `T09`, `T12`, `T13`)

### Core Scientific Questions
1. *Does the atomic model agree with the experimental diffraction amplitudes (`T03`, `T06`) or cryo-EM density map (`T04`, `T06`, `T08`), and is the free-set gap ($R_{\text{free}} - R_{\text{work}}$ or $FSC_{\text{work}} - FSC_{\text{free}}$) free of overfitting?*
2. *What ceiling do the raw experimental reflections (`T13`) or cryo-EM half-maps (`T12`) place on achievable model quality?*
3. *Did initial placement via molecular replacement (`T09`) or map docking (`T08`) find a genuine solution before coordinate refinement?*

### Task-by-Task Breakdown

#### `T03` — Reciprocal-space refinement (X-ray)
- **Documented capability**: Evaluates X-ray crystallographic coordinate, B-factor, occupancy, and TLS refinement by `phenix.refine`, `phenix.den_refine`, `phenix.rosetta_refine`, and `phenix.amber`. Catalog metrics: `T03_r-work`, `T03_r-free`, `T03_r-free_r-work_gap`, `T03_δr-free_vs_input`, `T03_bond_angle_rmsd`, `T03_molprobity_score`, `T03_clashscore`, and `T03_ramachandran_favored` (plus shared `T05_overall_b_mean`, `T05_total_atoms`, `T05_waters_count`). Oracles: `REFMAC5 (CCP4)`, `BUSTER`, `Servalcat`, and `gemmi rmsz`.
- **Runnable local integration**:
  - **Open-source (`top_performing`)**: External `gemmi` (`0.7.5`, resolved via `scripts/toolchain.py` `gemmi_executable()`) computes calculated structure factors via `gemmi sfcalc` (`REC_T03_r_work_top_performing_2026_09_22`, `REC_T03_r_free_top_performing_2026_09_22`). [`scripts/gemmi_rfactor.py`](../scripts/gemmi_rfactor.py) does not launch `gemmi sfcalc`; it reads two supplied MTZ files (`obs_mtz` and `calc_mtz` carrying `FC`), joins on `(H, K, L)`, and in the screening pipeline [`scripts/screen_round1.py`](../scripts/screen_round1.py) invokes `gemmi sfcalc --dmin=... --scale-to=... --to-mtz=...` and then passes both MTZs to `gemmi_rfactor.compute(..., 20)`. The current wrapper ([`scripts/gemmi_rfactor.py`](../scripts/gemmi_rfactor.py)) fits 20-bin scales on work reflections. The `1SAR` values (`0.1622 / 0.2136`) are retained historical bin-rescaled observations, not reruns of that current implementation; the retained original script (`data/coscientists/openscientist/gemmi_rfactor.py`) fits scales before splitting work and free reflections (`#937`). [`scripts/assess_refinement.py`](../scripts/assess_refinement.py) does not execute live $R$-factor calculations; it verifies the recorded `1SAR` observations (`0.1622 / 0.2136` on archived `1sar.mtz` and `1sar_final.mtz` in `data/coscientists/openscientist/cdba2c07-daff-4f60-ae96-12452b3a5fbb_artifacts.zip`) and replays the retained 22-structure control-cohort JSON summaries (`ref/research/data/negative_control_round3_bench.json`, `ref/research/data/negative_control_round4_recover.json`, `ref/research/data/negative_control_round10_recover.json`; `#937`).
  - **Retained reflection recount vs historical tool selection (`#934`)**: [`scripts/assess_refinement.py`](../scripts/assess_refinement.py) (via [`scripts/t03_reflection_retention.py`](../scripts/t03_reflection_retention.py)) recounts the archived `F-obs`, `SIGF-obs`, and `R-free-flags` columns in `1sar.mtz` and `1sar_final.mtz` (`6,494` positive-$F$ work and `723` `R-free-flags == 1` reflections preserved; `11` zero-$F$ work reflections converted to `NaN`). That archive column recount does not establish which effective reflections or free-set flags each historical executable used (`data/coscientists/openscientist/EVAL_1sar_cdba2c07_2026-09-23.yaml` lines `4277–4284` note matched selection/free flags are unestablished for the historical PHENIX start-to-final delta `0.3334 / 0.3956 -> 0.1564 / 0.2116`, lines `5015–5020` retain `REFMAC5` `0.1693 / 0.2128` without original raw output, and `Servalcat`'s historical record reports `n_free = 362`; effective selection and raw-output provenance remain incomplete).
  - **All-considered (`top_considered`)**: `Servalcat` and `REFMAC5` (`REC_T03_r_work_top_considered`, `REC_T03_r_free_top_considered`, `ASSUM_refmac_solvent_modelling`, `ASSUM_servalcat_sigmaa_per_shell_only`). `ASSUM_servalcat_refine_xtal_actually_refines` ([`ref/tool_assumptions.yaml`](tool_assumptions.yaml) lines `331–345`) records that `servalcat refine_xtal_norefmac` performs coordinate refinement by default, producing a modified model whose $R$-factor is not a re-measurement of the input model; retained benchmark scripts (`scripts/bench_round6.py` lines `222–235`, `scripts/bench_round7.py` lines `144–155`) invoke `servalcat refine_xtal_norefmac --ncycle 0`, though those commands alone do not establish input-coordinate invariance or cross-tool numerical equivalence (`#943`).

The benchmark doubles PISA's per-side interface area and discloses the difference between Biotite's protein selection and PISA's assembly-molecule surface.
- **Retained independent evidence**: The [BSA benchmark](research/tolerance_benchmark_interface_bsa.md) (`interface_bsa` in [`ref/threshold_evidence_status.yaml`](threshold_evidence_status.yaml)) retains the measured population and selection conventions supporting its scoped comparison. The [mapping-sensitivity record](research/tolerance_benchmark_selection_sensitivity.md) distinguishes controlled `DockQ` self-comparisons from the separately retained `1SAR` `A/B` comparison (`data/coscientists/openscientist/EVAL_1sar_cdba2c07_2026-09-21.yaml`, `data/coscientists/openscientist/EVIDENCE_1sar_cdba2c07_2026-09-21_bsa.json`, `data/coscientists/openscientist/EVIDENCE_1sar_cdba2c07_2026-09-21_dockq_AB_AB.json`, `data/coscientists/openscientist/EVIDENCE_1sar_cdba2c07_2026-09-21_dockq_AB_BA.json`). That `1SAR` pair is a crystallographic contact, not a certified biological assembly; its evidence does not establish biological-interface preservation.
- **Calibrated interpretation vs informational reporting**: Record the model, reference, selected chains, explicit mapping, and BSA atom/probe conventions. Apply [registered BSA and DockQ comparisons](thresholds_and_standards.md) (`T16_interface_buried_surface_area`, `T16_interface_dockq_score`) only with their stated applicability conditions; a high `DockQ` score does not establish that the reference or mapping is biologically correct. Keep the CAPRI class (`T16_capri_interface_quality_class`) descriptive and tied to the same `DockQ` comparison. Interface similarity does not establish biological assembly validity.

## 7. Category 5: Prediction Confidence & Predicted-Model Processing (`T07`)

### Core Scientific Questions
1. *Which regions of an AlphaFold2, AlphaFold3, ESMFold, or RoseTTAFold starting model are confident enough to use as molecular-replacement (`T09`) or map-docking (`T08`) templates, and how should pLDDT values be converted into crystallographic pseudo-$B$ factors?*
2. *How do self-reported prediction confidence scores (`pLDDT`, `PAE`, `pTM`, `ipTM`) differ from experimental coordinate accuracy (`lDDT`, `TM-score`)?*

### Task-by-Task Breakdown

#### `T07` — Predicted-model processing
- **Documented capability**: Processes structure predictions by trimming low-confidence regions, converting pLDDT to pseudo-$B$ factors, and splitting compact domains (`phenix.process_predicted_model`, `phenix.predict_model`, `phenix.predict_and_build`). Catalog metrics: `T07_fraction_residues_retained_after_trim`, `T07_mean_plddt_pre_post`, `T07_b-factor_1_plddt²_correlation`, `T07_domain_count_vs_pae_oracle`, `T07_rmsd_of_processed_model_vs_reference_experimental`, `T07_predicted_tm_score`, `T07_interface_predicted_tm_score`, and `T07_prediction_ensemble_convergence`. Oracles: `pae_to_domains.py (Croll/Tronrud)`, `biotite AF parsers`, `colabfold domain-splitter`, `ChimeraX alphafold`, `QMEANDisCo`, `TM-align`, and `OpenStructure`.
- **Runnable local integration**: Catalog recommendations identify confidence parsers (`REC_T07_mean_plddt_pre_post_top_considered`, `REC_T07_fraction_residues_retained_after_trim_top_considered`, `REC_T07_predicted_tm_score_top_considered`, `REC_T07_interface_predicted_tm_score_top_considered`, `T07_mean_plddt_pre_post`, `T07_fraction_residues_retained_after_trim`, `T07_b-factor_1_plddt²_correlation`, `T07_predicted_tm_score`, `T07_interface_predicted_tm_score`), PAE-based domain methods (`REC_T07_domain_count_vs_pae_oracle_top_considered`, `T07_domain_count_vs_pae_oracle`), and structural-comparison tools (`REC_T07_rmsd_of_processed_model_vs_reference_experimental_top_considered`, `T07_rmsd_of_processed_model_vs_reference_experimental`). For an actual run, record the predictor/version, original confidence field or matrix, coordinate subject, and selection used for each summary. AF2 per-residue pLDDT and AF3 per-atom pLDDT require explicitly different aggregation. A catalog recommendation does not itself establish an executed local integration.
- **Retained independent evidence**: The [`T07` driver](driving_example_T07.md) includes an engineering template for checking an independent parser on the same prediction output. It does not calibrate agreement between AF2 and AF3 predictions, and the [threshold inventory](threshold_evidence_status.yaml) supplies no metric-level literature-consensus record for that comparison.
- **Calibrated interpretation vs informational reporting**: `pLDDT`, `PAE`, `pTM`, and `ipTM` (`T07_mean_plddt_pre_post`, `T07_predicted_tm_score`, `T07_interface_predicted_tm_score`) are prediction-confidence outputs, not experimental validation. The [quality-reporting guide](quality_reporting.md) documents the empirical confidence-to-pseudo-$B$ conversion (`T07_b-factor_1_plddt²_correlation`, `T07_fraction_residues_retained_after_trim`) and its input/options requirements; pseudo-$B$ is not measured atomic displacement. Record trimming/domain-processing choices and the resulting subject. Inherited confidence does not validate refined coordinates; assess experimental fit or reference correspondence separately when appropriate evidence exists.

## 8. Category 6: Classification & Experimental-Restraint Specialization (`T15`, `T17`)

### Core Scientific Questions
1. *Does the model maintain a physically interpretable secondary-structure architecture and fold classification (`T15` `DSSP`, `STRIDE`, `biotite P-SEA`, `CATH`/`SCOPe`/`ECOD`), and when is cross-tool secondary-structure agreement interpretable?*
2. *For solution-NMR structures (`T17`), what is the conformer ensemble precision (ordered core vs disordered tails) and what distance/dihedral restraint information is reported in deposited validation files?*

### Task-by-Task Breakdown

#### `T15` — Structural/domain classification
- **Documented capability**: Oracle-only task assigning secondary-structure states (`H`/`E`/`C`) and domain/fold classifications. Catalog metrics: `T15_secondary_structure_agreement`, `T15_secondary_structure_content`, `T15_secondary_structure_assignment`, `T15_structural_domain_assignment`, and `T15_fold_classification`. Oracles: `DSSP`, `STRIDE`, `biotite P-SEA`, `CATH`, `SCOPe`, and `ECOD`.
- **Runnable local integration**: [`scripts/t15_ss_agreement.py`](../scripts/t15_ss_agreement.py) compares `mkdssp` secondary-structure assignments with Biotite P-SEA assignments after reducing them to `H`/`E`/`C` (`REC_T15_secondary_structure_assignment_top_considered`, `T15_secondary_structure_assignment`, `T15_secondary_structure_agreement`). The wrapper requires identical residue-key sets before scoring and records the per-assigner counts; a domain mismatch stops scoring rather than silently selecting a smaller denominator.
- **Retained independent evidence**: The [secondary-structure benchmark](research/tolerance_benchmark_ss_agreement.md) (`secondary_structure` in [`ref/threshold_evidence_status.yaml`](threshold_evidence_status.yaml), component `evidence_state: denominator_unproven`) retains the historical comparison of well-ordered X-ray references and disordered or coordinate-perturbed controls. Its per-assigner denominators were not retained, so the reported distribution is descriptive history rather than current calibration. The separate `1SAR` comparison is retained in `data/coscientists/openscientist/EVAL_1sar_cdba2c07_2026-09-22.yaml` and `data/coscientists/openscientist/EVIDENCE_1sar_cdba2c07_2026-09-22_t15.json`. The [stopped-run diagnostic](research/t15_failed_attempt_diagnostic_execution_2026-09-28.md) records unequal assignment domains without establishing missing backbone atoms or hetero-linkages as their cause.
- **Calibrated interpretation vs informational reporting**: `REC_T15_secondary_structure_agreement_top_considered_2026_09_22`, `REC_T15_secondary_structure_agreement_top_performing_2026_09_22`, and `REC_T15_secondary_structure_content_top_considered` require reading agreement (`T15_secondary_structure_agreement`) alongside DSSP `H+E` content (`T15_secondary_structure_content`). The [registry](thresholds_and_standards.md) treats the content precondition and cross-method agreement expectation as provisional and informational pending exact-denominator recalibration. High agreement dominated by coil assignments is weak evidence, and low secondary-structure content does not itself fail model quality. The separate agent-versus-DSSP comparison ([`ref/structural_criteria.yaml`](structural_criteria.yaml)) requires agent-supplied labels and remains unmeasured by this paired-assigner benchmark.

#### `T17` — NMR ensemble/restraint validation
- **Documented capability**: Oracle-only task evaluating NMR conformer bundle precision, per-residue RMSF, and experimental distance/dihedral restraint violations. Catalog metrics: `T17_nmr_restraint_violation_summary` and `T17_nmr_ensemble_precision_rmsd`. Oracles: `wwPDB NMR validation`, `PROCHECK-NMR`, `RPF`, and `biotite ensemble`.
- **Runnable local integration**: [`scripts/t17_nmr_ensemble.py`](../scripts/t17_nmr_ensemble.py) (`REC_T17_nmr_ensemble_precision_rmsd_top_considered`, `REC_T17_nmr_ensemble_precision_rmsd_top_performing`, `T17_nmr_ensemble_precision_rmsd`) superposes conformer $\text{C}\alpha$ coordinates onto the first model, computes per-residue RMSF around the superposed ensemble mean, and reports the mean over residues with $\text{RMSF} \le 2.0\text{ Å}$ alongside whole-chain summaries. [`scripts/t17_restraint_summary.py`](../scripts/t17_restraint_summary.py) (`REC_T17_nmr_restraint_violation_summary_top_considered`, `REC_T17_nmr_restraint_violation_summary_top_performing`, `T17_nmr_restraint_violation_summary`) reads deposited wwPDB XML distance-violation bins, mean distance violations, and restraint totals, including the total dihedral-restraint count. It does not extract an angular-threshold dihedral-violation count or recompute violations from raw restraints; absent restraint data cause an explicit failure.
- **Retained independent evidence**: The [selection-sensitivity record](research/tolerance_benchmark_selection_sensitivity.md) varies the ordered-core cutoff within the same implementation. It demonstrates sensitivity to selection convention, not an independently measured cross-tool noise floor. The retained `1D3Z` precision example and `2N54` restraint-report example are documented in [oracle guidance](oracle_tools.md); the legacy `1D3Z` report lacks the required restraint section.
- **Calibrated interpretation vs informational reporting**: Report the core cutoff, residue population, and whole-chain summary with ensemble precision (`T17_nmr_ensemble_precision_rmsd`). Use the [registry's conditional comparison guidance](thresholds_and_standards.md) only within its stated scope; the sensitivity experiment does not independently calibrate agreement between different implementations. Precision and deposited restraint summaries (`T17_nmr_restraint_violation_summary`) remain descriptive, with no fixed absolute precision-quality tiers. Missing restraint information is not evidence of zero violations.

## 9. Synthesis: Using This Guide in Before/After Refinement Assessment (`scripts/assess_refinement.py`)

When evaluating a structure refinement run with [`scripts/assess_refinement.py`](../scripts/assess_refinement.py) (see case study in [`ref/research/refinement_assessment_case_study_2026-10-18.md`](research/refinement_assessment_case_study_2026-10-18.md) and review audit trail in [`ref/research/pr916_review_audit_trail_2026-10-18.md`](research/pr916_review_audit_trail_2026-10-18.md)), the 6 question categories map directly onto the **three orthogonal evaluation questions** required by Goal 1:

| Assessment Question | Question Categories & Tasks Invoked | Retained evidence and fresh arithmetic |
|---|---|---|
| **1. Do implementations agree on the same observable?** | **Category 1 (`T03`, `T06`)** + **Category 2 (`T05`, `T14`)** + **Category 6 (`T15`)** | Compare retained observations of the same observable and subject where compatible operands exist. Identify producers, selections, estimator/library differences, and missing independent coverage; agreement and provenance are separate claims. |
| **2. What supports the final model's quality for its intended use?** | **Category 1 (`T03`, `T06`, `T13`)** + **Category 2 (`T05`)** + **Category 3 (`T01`)** + **Category 4 (`T10`, `T16`)** + **Category 6 (`T15`)** | Report evidence for the retained final subject and its intended use, including available fit, geometry, and local-site observations. Preserve missing measurements and criteria (`ref/thresholds_and_standards.md`, `#911` `ProSMART` deprecated for `T05_rama_z_score`); an informational observation or synthetic example is not a quality pass. |
| **3. What improved or regressed relative to the actual input?** | **Category 3 (`T01`, `T02`, `T11`)** + **Deltas across Categories 1, 2, 4, 6** | Combine fresh archive-coordinate/inventory arithmetic with retained historical measurement deltas where both endpoints support the comparison. Keep per-target control summaries separate from atom-level `1SAR` summaries, and do not infer a unique cause or validate the absent round-7 model. |
